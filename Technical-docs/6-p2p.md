# P2P Confidential Lending — Technical Documentation

## Overview

Peer-to-Peer (P2P) Confidential Lending in Walnut Protocol expands borrowing beyond automated liquidity pools into direct, bilateral borrower-lender agreements. On traditional public P2P protocols (such as Morpho Blue or NFT-collateralized lending platforms), loan terms, interest rates, borrower collateral ratios, and wallet addresses are publicly broadcasted on-chain. 

Walnut's P2P architecture leverages Fully Homomorphic Encryption (FHE) to enable **Sealed-Offer Order Matching** and **Private Bilateral Escrows**, allowing borrowers and institutional lenders to negotiate, match, and service custom loans with complete confidentiality.

---

## How It Works Under the Hood

### 1. The P2P Confidentiality Problem
In conventional public P2P lending:
- Lenders broadcast plaintext order books specifying maximum loan amounts, acceptable collateral assets, and requested interest rates.
- Competitors front-run or undercut interest rates.
- Borrowers reveal their exact liquidity needs and risk profile to public observers.

Walnut eliminates this by encrypting all order book terms using CoFHE primitives (`euint128`).

### 2. Sealed-Offer Matching Architecture
Instead of maintaining an open, unencrypted order book:

1. **Encrypted Lender Offers:** Lenders create confidential lending commitments by locking capital into an FHE-shielded P2P vault (`WalnutFHERC20`). Target interest rates, duration, and collateral ratios are submitted as ciphertext structures (`InEuint128`).
2. **Encrypted Borrower Requests:** Borrowers post ciphertext borrow requests detailing required principal and pledged collateral.
3. **On-Chain Homomorphic Matching:** Smart contract logic compares encrypted borrower parameters against encrypted lender parameters using FHE relational operators (`FHE.gte`, `FHE.lte`, `FHE.select`):

```solidity
// Homomorphic matching logic checks if borrower collateral meets lender threshold
ebool isCollateralSufficient = FHE.gte(borrowerCollateralUSD, requiredCollateralUSD);
ebool isRateAcceptable      = FHE.lte(offeredInterestRate, maxBorrowerRate);

// Match succeeds only if both conditions evaluate to true in ciphertext
ebool isMatchValid = FHE.and(isCollateralSufficient, isRateAcceptable);
```

4. **Zero-Knowledge Match Execution:** If `isMatchValid` evaluates to true, the contract executes the loan match automatically without ever revealing the underlying interest rate or principal amount to external observers.

### 3. Bilateral Escrow & Isolated Risk Isolation
Unlike pooled lending where depositor capital is combined into a single vault exposed to shared bad debt, P2P confidential lending operates via isolated bilateral escrows:

- **Collateral Isolation:** Borrower collateral is locked into a dedicated vault mapping (`_vaults[borrower]`) tied specifically to the lender's commitment.
- **Customized Duration & APR:** Fixed-term loan expiry timestamps and fixed APR percentages are enforced on-chain.
- **Encrypted Repayment Routing:** Repayments flow directly from borrower to lender via `stablecoin.burnInternal` and `stablecoin.mintInternal`, bypassing global pool rebalancing.

## Technical Highlights & Under-the-Hood Points

- **No Pool Dilution:** Lenders retain 100% control over counterparty risk, asset selection, and interest rate setting without exposure to third-party borrower defaults.
- **Selective Institutional Disclosure:** Institutional lenders requiring compliance reporting can grant permissioned decryption permits (`FHE.allow`) exclusively to approved auditors without broadcasting positions to the public chain.
- **Protection Against Front-Running:** Order books cannot be scraped by MEV bots to front-run interest rate offers or target vulnerable borrowers.
- **Credit Tier Integration:** P2P lenders can set minimum credit tier requirements (e.g. requiring Credit Tier 2+ derived from encrypted repayment history) prior to match execution.
